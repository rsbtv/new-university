# Программа на Qt C++ QML 5.15.3. 
## Парсинг из config.json.
Парсится следующее:
1) Название программы на английском и русском
2) Modbus-подключения, в которых:
    2.1) Уникальный int индекс (доступно для QML)
    2.2) Уникальное название на английском и русском (доступно для QML)
    2.3) ip
    2.4) порт
    2.5) slaveId
    2.6) тип регистра (holding/input etc)
    2.7) Модели данных datamodels, в которых:
            2.7.1) Уникальный int индекс (доступно для QML)
            2.7.2) Не уникальное название на английском и русском (доступно для QML) 
            2.7.3) Название девайса на русском и английском (доступно для QML)
            2.7.4) Название контейнера на русском и английском (доступно для QML)
            2.7.5) Тип данных: bool/outputBool
            2.7.6) Номер регистра
            2.7.7) Номер бита

## Modbus-подключения.
Реализуются с помощью класса ModbusConnection. Помимо помеченных 
как доступные для QML, должен быть публичные и тоже доступные для QML атрибуты: 
адрес (ip+port), ошибка(если есть таковая) и статус подключения (нет связи/подключено).

## Модели данных. 
Сейчас на данный момент нужны 2 основных класса: 
1) BoolValue:
  Они собираются из json`а. 
  У них должен быть геттер bool connected() (доступно для QML) - статус подключения - подключён/не подключён. 
  Также должен быть геттер bool value() (доступно для QML) - состояние бита, к которому привзязан экземпляр этого класса
  Также должен быть геттер QString valueString() (доступно для QML) - текстовое описание состояния 
2) OutputBoolValue:
    Наследуется от BoolValue, но имеет сеттер setValue(bool value).

Помимо этого должны быть реализованы классы, которые собираются из этих самых BoolValue и OutputBoolValue.
1) Qf. Включает в себя BoolValue* onValue и BoolValue* offValue. Так как два разных бита отвечают за состояние. 
Тоже должны быть connected(), value(), valueString() - все доступны для QML. 

3) QfWithCommands - наследуется от Qf, но есть ещё OutputBoolValue* commandOn, OutputBoolValue*  commandOff; доступный для QML
сеттер setOn(), setOff(), в которых соответственно вызываются setValue() для полей класса в виде OutputBoolValue.

4) QfOneCommand - имеет всего одну модель данных в качестве поля - OutputBoolValue. Один бит отвечает и за команду вкл,
и команду выкл, и состояние.

3) TwoBitsIndicator. Один бит (BoolValue* lowValue) отвечает за состояние "Ниже нормы",
другой бит (BoolValue* highValue) отвечает за состояние "Выше нормы".
Если оба бита выключены - состояние "Норма", иначе "Неизвестно".

## QML-реализации.

Основное окно состоит из следующих элементов:
В шапке страницы название программмы, в правой её части - дата и время.
Потом на всю длину идёт Repeater из ConnectionPanel, в который передаются ModbusConnection`ы и
отображаются: Название, адрес, ошибка (если есть), статус подключения.

Далее идут две равные по длине колонки на всю ширину, в которые я могу по своему желанию разместить следующие элементы:
1) Container. Слева - передаваемое название; справа - делится на две строки, в которые я могу разместить:
    1.1) QfRow. Слева - передаваемое название, справа - индикатор состояние (просто строка в квадратике на цветном фоне).
    1.2) QfWithCommandsRow. Так же как и QfRow, но добавляются  две кнопки с соответствующими привязанными к ним функциям.
2) TwoBitsIndicatorRow. Слева - передаваемое название, справа - три прямоугольника: Ниже нормы (красный цвет, когда активен, иначе - серый),
    Норма (зеленый, когда активен, иначе - серый), Выше нормы (так же как и с "Ниже нормы").
3) QfOneCommandRow. Название, две кнопки (одна выставляет бит в единицу, другая - в ноль), прямоугольник с надписью состояния.

Интерфейс должен быть адаптирован под 1920x1080. Размеры шрифтов, отступов, пробелов и т.п. задаются константами, 
когда это целесообразно.

Интерфейс должен быть простой, с темным фоном.

## Упрощённое изложение алгоритма работы программы
1) В основном классе-инициализаторе инициализируется парсер конфига.
2) В парсере создаются BoolValue и OutputBoolValue и закидываются в список
3) Я будучи программистом должен иметь доступ к ним по имение через соответствующий метод, обращаясь к экземпляру класса парсера.
4) Позже опять-таки я собираю экземлпяры составных классов (Qf, QfWithCommands, QfOneCommand, TwoBitsIndicator)
5) Опрос идет батчем регистров целыми регистрами. 

## Требования к коду.

Код должен документироваться внутренними средствами, система должна быть в целом расширяемой, читаемой и поддерживаемой, понятной программисту. Должны соблюдаться стандарты ООП: разделение ответственности между классами, инкапсуляция, понятные интерфейсы. Используй сигналы и слоты Qt для реакции на подключение, ошибки, завершение запросов и результаты опроса.
Обрабатывай типичные ошибки.


Не нужно использовать плохо читаемый синтаксический сахар вроде анонимных пространств имен, как можно меньше шаблонов. 
Максимально должны использоваться внутренние библиотеки для протокола Modbus и как можно
меньше кастомных решений.
