## Вопрос 1. ИИ, машинное обучение и глубокое обучение. Место нейросетей. Основные типы задач

**Искусственный интеллект (ИИ)** — область науки о создании систем, выполняющих задачи, традиционно требующие человеческого интеллекта: распознавание образов, понимание языка, принятие решений. Включает и системы на правилах (экспертные системы), и обучающиеся.

**Машинное обучение (МО)** — раздел ИИ, где система не получает готовых правил, а выводит их из данных. Классическое программирование: правила + данные → результат. МО: данные + ответы → правила (модель).

**Глубокое обучение (ГО)** — подраздел МО на основе многослойных нейронных сетей. «Глубина» = много последовательных слоёв, каждый извлекает всё более абстрактные признаки. Главное отличие от классического МО: признаки не конструируются вручную, сеть строит их сама.

Соотношение — вложенные множества: ГО ⊂ МО ⊂ ИИ.

**Место нейросетей.** Нейросети — универсальный аппроксиматор зависимостей. В анализе табличных данных конкурируют с классическим МО, но незаменимы там, где признаки сложно задать вручную: изображения, космо- и аэроснимки, видео, текст, звук. Для пространственных данных (ДЗЗ, карты) CNN извлекают локальные пространственные признаки: границы, текстуры, формы объектов.

**Основные типы задач:**

- **Регрессия** — предсказание непрерывного числа (цена квартиры, температура, урожайность).
- **Классификация** — отнесение объекта к одному из классов (кошка/собака, спам/не спам). Результат — класс всего объекта.
- **Семантическая сегментация** — классификация каждого пикселя изображения (этот пиксель — дорога, этот — здание). Результат — маска размером с изображение.
- **Детекция объектов** — поиск объектов на изображении: класс + ограничивающая рамка (bounding box) для каждого найденного объекта.

## Вопрос 2. Искусственный нейрон

**Искусственный нейрон** — базовый вычислительный элемент сети, упрощённая модель биологического нейрона. Принимает несколько чисел, выдаёт одно.

**Компоненты и порядок вычисления:**

1. **Входные признаки** x₁, x₂, …, xₙ — числа (пиксели, площадь, возраст…).
2. **Веса** w₁, …, wₙ — обучаемые параметры; вес показывает важность и направление влияния признака.
3. **Смещение (bias)** b — обучаемый сдвиг, позволяет нейрону активироваться даже при нулевых входах (аналог свободного члена в линейной функции).
4. **Взвешенная сумма:** z = w₁x₁ + w₂x₂ + … + wₙxₙ + b = w·x + b.
5. **Функция активации** f — нелинейное преобразование суммы.
6. **Выход:** y = f(z).

```python
import numpy as np
def neuron(x, w, b):
    z = np.dot(w, x) + b      # взвешенная сумма
    return max(0, z)          # активация ReLU
```

**Слой нейронов** — несколько нейронов, каждый получает один и тот же входной вектор, но имеет свои веса и смещение. Вычисление всего слоя — матричная операция: **y = f(W·x + b)**, где W — матрица весов (строка = веса одного нейрона), b — вектор смещений. Выход слоя — вектор из выходов всех его нейронов, который идёт на вход следующему слою.

## Вопрос 3. Структура нейронной сети

**Нейронная сеть** — набор нейронов, организованных в последовательные слои.

- **Входной слой** — не вычисляет, а принимает данные; число «нейронов» = числу признаков (например, 784 для изображения 28×28 в виде вектора).
- **Скрытые слои** — промежуточные слои между входом и выходом; выполняют последовательные нелинейные преобразования, извлекая закономерности. Их выходы не видны пользователю напрямую.
- **Выходной слой** — формирует ответ; его размер и активация определяются задачей (1 нейрон для регрессии, N нейронов с softmax для N классов).

**Полносвязный (Dense) слой** — каждый нейрон слоя соединён со всеми выходами предыдущего слоя. Число параметров слоя = n_входов × n_нейронов + n_нейронов (смещения).

**Ширина** — число нейронов в слое. **Глубина** — число слоёв. Сеть с ≥2 скрытыми слоями обычно называют глубокой.

**Связь архитектуры с выявлением закономерностей:** один слой без нелинейности способен выразить только линейную зависимость. Каждый добавленный нелинейный слой строит признаки на основе признаков предыдущего: первые слои находят простые комбинации входов, глубокие — сложные абстракции. Чем больше нейронов и слоёв, тем сложнее зависимости сеть способна представить, но тем больше данных нужно для обучения и тем выше риск переобучения. Архитектуру подбирают под сложность задачи.

```python
model = keras.Sequential([
    layers.Dense(64, activation="relu", input_shape=(10,)),  # скрытый
    layers.Dense(32, activation="relu"),                     # скрытый
    layers.Dense(1)                                          # выходной (регрессия)
])
```

## Вопрос 4. Прямое распространение сигнала (forward propagation)

**Прямое распространение** — процесс вычисления предсказания: входные данные последовательно проходят через все слои от входа к выходу.

**Механизм.** Каждый слой берёт выход предыдущего, применяет своё линейное преобразование и активацию:

```
a⁰ = x  (вход)
a¹ = f₁(W¹·a⁰ + b¹)
a² = f₂(W²·a¹ + b²)
...
ŷ = fₖ(Wᵏ·aᵏ⁻¹ + bᵏ)  (выход)
```

Данные «текут» в одну сторону, никаких обновлений весов при этом не происходит — только вычисление. Именно forward pass выполняется и при обучении (чтобы посчитать ошибку), и при использовании готовой модели (`model.predict`).

**Получение предсказания:**

- **Регрессия:** выходной слой — 1 нейрон с линейной (тождественной) активацией; выход сети — само предсказанное число (цена, температура).
- **Бинарная классификация:** 1 нейрон с sigmoid; выход — вероятность класса «1»; порог 0.5 превращает её в метку.
- **Многоклассовая классификация:** N нейронов с softmax; выход — вектор вероятностей классов, сумма = 1; предсказанный класс — argmax.

```python
probs = model.predict(X)          # вектор вероятностей
y_pred = np.argmax(probs, axis=1) # индекс класса
```

## Вопрос 5. Функции активации

**Функция активации** — нелинейное преобразование, применяемое к взвешенной сумме нейрона.

**Зачем нелинейность.** Композиция любых линейных функций — снова линейная функция. Без активаций сеть из 100 слоёв эквивалентна одному линейному слою и не сможет выучить сложные зависимости (даже XOR). Нелинейность даёт сети способность аппроксимировать произвольные функции.

**Основные функции:**

- **ReLU:** f(z) = max(0, z). Отрицательное → 0, положительное → без изменений. Быстро вычисляется, не насыщается при z > 0, поэтому градиенты не затухают. Стандарт для **скрытых слоёв** (Dense и CNN). Недостаток — «мёртвые нейроны» (навсегда ушедшие в 0).
- **Sigmoid:** σ(z) = 1/(1+e⁻ᶻ). Сжимает любое число в (0, 1) — интерпретируется как вероятность. Используется в **выходном слое бинарной классификации** (а также для пиксельных масок в сегментации с 2 классами). В скрытых слоях почти не применяется: насыщение → затухающие градиенты.
- **Softmax:** softmax(zᵢ) = e^{zᵢ} / Σe^{zⱼ}. Превращает вектор N чисел в распределение вероятностей (все в (0,1), сумма 1). Используется только в **выходном слое многоклассовой классификации**.

**Типичные применения:**

| Где | Функция |
|---|---|
| Скрытые слои | ReLU (или вариации: LeakyReLU, ELU) |
| Выход: регрессия | линейная (нет активации) |
| Выход: 2 класса | sigmoid |
| Выход: N классов | softmax |

## Вопрос 6. Функции потерь

**Функция потерь (loss)** — число, измеряющее, насколько предсказания модели расходятся с правильными ответами. Это то, что оптимизатор минимизирует при обучении; она должна быть дифференцируемой.

**Связь с типом задачи** — потери выбирают согласованно с выходным слоем и форматом целевой переменной.

**Регрессия:**

- **MSE** (mean squared error) — средний квадрат ошибки: MSE = (1/n)Σ(yᵢ−ŷᵢ)². Сильно штрафует большие ошибки, чувствительна к выбросам. Стандартный выбор.
- **MAE** (mean absolute error) — средний модуль ошибки: MAE = (1/n)Σ|yᵢ−ŷᵢ|. Устойчивее к выбросам, интерпретируется в единицах целевой величины.

**Классификация — кросс-энтропия** (штрафует уверенные неправильные предсказания логарифмически сильно):

- **Binary crossentropy:** L = −[y·log(p) + (1−y)·log(1−p)] — для 2 классов, выход sigmoid, метка 0/1.
- **Categorical crossentropy:** L = −Σ yᵢ·log(pᵢ) — для N классов, выход softmax, метки в **one-hot** виде ([0,0,1,0]).
- **Sparse categorical crossentropy** — та же формула, но метки — целые числа (2), без one-hot.

**Таблица согласования (критично знать):**

| Задача | Выходной слой | Loss | Формат y |
|---|---|---|---|
| Регрессия | Dense(1), линейная | MSE / MAE | число |
| 2 класса | Dense(1), sigmoid | binary_crossentropy | 0 или 1 |
| N классов | Dense(N), softmax | categorical_crossentropy | one-hot |
| N классов | Dense(N), softmax | sparse_categorical_crossentropy | целое число |

## Вопрос 7. Метрики качества моделей

**Отличие метрики от функции потерь.** Loss — для оптимизатора: дифференцируема, минимизируется градиентным спуском. Метрика — для человека: интерпретируемая оценка качества, в обучении не участвует, может быть недифференцируемой (accuracy). Loss = «как учимся», метрика = «насколько хороши».

**Метрики регрессии:** MAE (средняя ошибка в единицах величины), MSE/RMSE (корень из MSE — тоже в единицах величины), R² (доля объяснённой дисперсии, 1 — идеал).

**Метрики классификации** (через матрицу ошибок):

**Матрица ошибок (confusion matrix)** — таблица «истинный класс × предсказанный класс»: TP (верно «да»), TN (верно «нет»), FP (ложная тревога), FN (пропуск).

- **Accuracy** = (TP+TN)/всё — доля верных ответов. Обманчива при дисбалансе: если 99% объектов класса «0», модель «всегда 0» даёт accuracy 0.99.
- **Precision** = TP/(TP+FP) — точность: из предсказанных «да» сколько действительно «да». Важна, когда дорога ложная тревога (спам-фильтр).
- **Recall** = TP/(TP+FN) — полнота: из реальных «да» сколько нашли. Важна, когда дорог пропуск (диагностика болезни).
- **F1-score** = 2·P·R/(P+R) — гармоническое среднее precision и recall, сбалансированная единая оценка.

**Интерпретация по нескольким метрикам:** одной метрики мало. Высокая accuracy + низкий recall по редкому классу = модель игнорирует редкий класс. Высокий recall + низкий precision = модель «кричит про всё подряд». Смотрят матрицу ошибок и per-class метрики (`classification_report`), выбирая баланс под цену ошибок в прикладной задаче.

## Вопрос 8. Обучающая, валидационная и тестовая выборки

Данные делят на три непересекающиеся части (типично 70/15/15 или 80/10/10):

- **Train (обучающая)** — на ней модель учится: по ней считаются градиенты и обновляются веса.
- **Validation (валидационная)** — проверка во время обучения на данных, которые модель не видела при обновлении весов. По ней: подбирают гиперпараметры, отслеживают переобучение (val_loss растёт при падающем train loss), останавливают обучение (EarlyStopping), выбирают лучшую эпоху (ModelCheckpoint). Так как по val принимаются решения, модель косвенно «подгоняется» под неё.
- **Test (тестовая)** — используется **один раз в конце** для честной итоговой оценки. Не участвует ни в обучении, ни в выборе модели.

**Зачем оценивать на невиданных данных:** цель модели — обобщение, а не запоминание. Качество на train всегда завышено: модель могла просто запомнить примеры. Только данные вне обучения показывают, как модель поведёт себя в реальности.

```python
from sklearn.model_selection import train_test_split
X_tr, X_test, y_tr, y_test = train_test_split(X, y, test_size=0.15, random_state=42)
model.fit(X_tr, y_tr, validation_split=0.15, epochs=50)  # часть train — на валидацию
model.evaluate(X_test, y_test)                            # финальная оценка
```

Важно: все преобразования (масштабирование) настраиваются только на train (`scaler.fit(X_train)`), иначе — утечка данных.

## Вопрос 9. Градиентный спуск

**Идея.** Обучение сети = поиск весов, минимизирующих функцию потерь. Представьте потери как рельеф над пространством параметров; нужно спуститься в низину.

**Градиент** — вектор частных производных потерь по всем параметрам: ∇L = (∂L/∂w₁, …, ∂L/∂b). Указывает направление наискорейшего **роста** потерь. Поэтому шагаем в противоположную сторону.

**Правило обновления:**

```
w_new = w_old − η · ∂L/∂w
```

где **η (learning rate, скорость обучения)** — размер шага, главный гиперпараметр оптимизации.

**Цикл:** forward pass → вычислить loss → вычислить градиенты (backprop) → обновить параметры → повторить.

**Проблемы выбора шага:**

- **Слишком большой η:** перепрыгиваем минимум, loss скачет или растёт, обучение расходится (loss → NaN).
- **Слишком маленький η:** обучение мучительно медленное; риск застрять в локальном минимуме или на плато; за разумное число эпох сеть не доучится.
- Практика: начинать с типичного значения (например, 0.001 для Adam), уменьшать при нестабильности, использовать расписания/адаптивные методы.

**Стохастический вариант (SGD):** градиент считается не по всем данным, а по мини-батчу — быстрее и вносит полезный шум, помогающий выбираться из мелких локальных минимумов.

## Вопрос 10. Обратное распространение ошибки (backpropagation)

**Задача:** для градиентного спуска нужны производные потерь по **каждому** параметру сети (а их миллионы). Backpropagation — эффективный алгоритм их вычисления.

**Общая идея.** Ошибка известна на выходе сети. Сеть — композиция функций, поэтому по **правилу цепочки (chain rule)** производную потерь по любому весу можно разложить через производные всех слоёв между этим весом и выходом:

```
∂L/∂w = ∂L/∂ŷ · ∂ŷ/∂a · ∂a/∂z · ∂z/∂w
```

Алгоритм идёт **от выходного слоя к входному**, послойно «распространяя ошибку назад»: вычислив вклад в ошибку нейронов слоя k, легко вычислить вклад нейронов слоя k−1. Промежуточные результаты переиспользуются, поэтому все градиенты считаются за один обратный проход — это и делает обучение глубоких сетей практически возможным.

Интуиция: каждый параметр получает «свою долю вины» за итоговую ошибку — пропорционально тому, насколько его изменение повлияло бы на выход.

**Связь с градиентным спуском:** backprop **вычисляет** градиенты, градиентный спуск **использует** их для обновления весов. Полный шаг обучения:

1. Forward pass → предсказание ŷ.
2. Loss L(ŷ, y).
3. Backward pass (backprop) → ∂L/∂w для всех параметров.
4. Обновление: w ← w − η·∂L/∂w.

В Keras всё это скрыто внутри `model.fit()` (автоматическое дифференцирование).

## Вопрос 11. Оптимизаторы

**Оптимизатор** — алгоритм, определяющий, **как именно** обновлять параметры по вычисленным градиентам. Цель — быстрее и стабильнее привести модель к низким потерям.

**SGD (stochastic gradient descent).** Базовый: w ← w − η·g, где g — градиент по мини-батчу. Один общий learning rate для всех параметров. Прост, но: медленно идёт по «оврагам», чувствителен к выбору η. Обычно дополняется **momentum** (инерция: накапливается сглаженное направление движения, шаги по согласованному направлению ускоряются, колебания гасятся).

**Adam (adaptive moment estimation).** Самый популярный. Хранит для каждого параметра две скользящие оценки: среднего градиента (момент 1, аналог momentum) и среднего квадрата градиента (момент 2). Шаг по каждому параметру масштабируется: параметры с большими/частыми градиентами получают меньший эффективный шаг, с редкими/малыми — больший. Итог: **адаптивный индивидуальный learning rate для каждого параметра**, быстрая и устойчивая сходимость почти «из коробки» (стартовое η = 0.001).

**Роль learning rate:** глобальный масштаб шага задаёт пользователь даже для Adam; адаптивность лишь корректирует его по параметрам. Слишком большой — расходимость, слишком маленький — медленно (см. вопрос 9). Полезно уменьшать η по ходу обучения (расписания, ReduceLROnPlateau) — крупные шаги в начале, точная подстройка в конце.

```python
model.compile(optimizer=keras.optimizers.Adam(learning_rate=0.001), loss="mse")
```

## Вопрос 12. Гиперпараметры обучения

**Гиперпараметры** — настройки, задаваемые человеком до обучения (в отличие от параметров-весов, которые сеть учит сама).

**Основные:**

- **Число эпох** — сколько раз сеть проходит весь обучающий набор. Мало → недообучение; много → переобучение и трата времени. Практика: ставить с запасом + EarlyStopping.
- **Размер батча (batch size)** — число примеров на одно обновление весов. Маленький (8–32): шумные градиенты, медленнее по времени, но шум помогает обобщению. Большой (256+): стабильные градиенты, быстрее на GPU, но требует памяти и может ухудшить обобщение. Типично 32–64.
- **Скорость обучения (learning rate)** — самый важный. Влияет на сходимость и устойчивость (вопросы 9, 11).
- **Размер и сложность модели** — число слоёв, нейронов, фильтров. Маленькая модель → недообучение (не хватает ёмкости); большая → переобучение на малых данных, дольше обучение.

Также: выбор оптимизатора, функции активации, доля dropout, коэффициенты регуляризации.

**Влияние:**

| Гиперпараметр | На скорость | На устойчивость | На обобщение |
|---|---|---|---|
| LR ↑ | быстрее | риск расходимости | может не сойтись |
| Батч ↑ | быстрее/эпоха | стабильнее | иногда хуже |
| Эпохи ↑ | дольше | — | риск переобучения |
| Модель ↑ | дольше | сложнее обучать | мощнее, но риск переобучения |

Подбор — по **валидационной** выборке: меняем гиперпараметр, сравниваем val-метрики.

## Вопрос 13. Графики обучения модели

**История обучения в Keras.** `model.fit()` возвращает объект `History`; `history.history` — словарь со значениями loss и метрик по эпохам: `loss`, `accuracy`, `val_loss`, `val_accuracy`. По нему строят графики «метрика vs эпоха» для train и validation.

```python
h = model.fit(X, y, validation_split=0.2, epochs=50)
plt.plot(h.history["loss"], label="train")
plt.plot(h.history["val_loss"], label="val")
```

**Диагностика по графикам:**

- **Нормальное обучение:** train loss и val loss оба плавно снижаются, идут близко, выходят на плато. Небольшой зазор (train чуть лучше) — норма.
- **Переобучение:** train loss продолжает падать, а **val loss достигает минимума и начинает расти**; зазор между кривыми увеличивается. Модель запоминает train. Лечение: остановиться на минимуме val_loss (EarlyStopping), регуляризация, больше данных.
- **Недообучение:** обе кривые остановились на высоком уровне потерь / низких метриках, train-метрики тоже плохие. Модель слишком проста или обучение слишком короткое/медленное. Лечение: больше слоёв/нейронов, больше эпох, выше LR.
- **Нестабильное обучение:** loss скачет вверх-вниз, резкие пики, иногда рост или NaN. Причины: слишком большой learning rate, слишком маленький батч, немасштабированные данные. Лечение: уменьшить LR, увеличить батч, нормализовать входы, BatchNorm.

## Вопрос 14. Подготовка данных для нейронных сетей

Нейросеть принимает только числовые тензоры одинаковой формы, и качество данных определяет качество модели.

**Этапы:**

1. **Очистка** — обработка пропусков (удаление строк или заполнение средним/медианой/модой), удаление дубликатов, обработка выбросов и явных ошибок.
2. **Масштабирование признаков** — приведение к сопоставимым диапазонам, иначе признак «зарплата (десятки тысяч)» задавит «возраст (десятки)», а градиентный спуск будет нестабилен.
   - Нормализация MinMaxScaler → [0, 1];
   - Стандартизация StandardScaler → среднее 0, σ = 1.
   - **fit только на train**, transform — на всё (иначе утечка данных).
3. **Кодирование категорий и целевых переменных** — текст → числа: LabelEncoder (класс → целое), one-hot/`to_categorical` (класс → вектор [0,1,0]) — формат должен соответствовать функции потерь (вопрос 6).
4. **Преобразование форматов** — приведение к нужной форме тензора: float32, reshape.
5. **Разбиение на выборки** — train/val/test (вопрос 8), при классификации — со стратификацией (сохранение пропорций классов).

**Табличные данные:** главное — очистка, кодирование категориальных признаков, масштабирование каждого столбца; вход — вектор признаков.

**Изображения:** нормализация пикселей (деление на 255 → [0,1]); приведение к единому размеру (resize); форма (высота, ширина, каналы) для CNN или вектор для Dense; при нехватке данных — **аугментация** (повороты, отражения, сдвиги — создаёт новые варианты без новой съёмки).

## Вопрос 15. Жизненный цикл модели в Keras

Стандартная последовательность работы с моделью:

**1. Создание архитектуры и добавление слоёв** — описываем структуру: типы слоёв, число нейронов, активации.

```python
model = keras.Sequential([
    layers.Dense(64, activation="relu", input_shape=(10,)),
    layers.Dense(32, activation="relu"),
    layers.Dense(3, activation="softmax"),
])
```

**2. Компиляция** — `model.compile(...)`: указываем оптимизатор (как обновлять веса), функцию потерь (что минимизировать) и метрики (что показывать человеку). До компиляции обучение невозможно.

```python
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
```

**3. Обучение** — `model.fit(X, y, epochs, batch_size, validation_split/validation_data, callbacks)`: цикл forward → loss → backprop → обновление весов; возвращает History для графиков.

**4. Оценка качества** — `model.evaluate(X_test, y_test)`: вычисляет loss и метрики на тестовых данных без обучения.

**5. Предсказания** — `model.predict(X_new)`: только forward pass; для классификации возвращает вероятности (далее argmax → класс).

**6. Сохранение и загрузка** — `model.save("model.keras")` сохраняет архитектуру + веса + состояние оптимизатора; `keras.models.load_model(...)` — восстановление для инференса без переобучения.

Назначение этапов: разделить описание модели (1–2), её настройку под задачу (2), обучение (3), честную проверку (4) и эксплуатацию (5–6).

## Вопрос 16. Полносвязные сети в регрессии и классификации

**Dense-архитектура** — стек полносвязных слоёв: вход → несколько Dense+ReLU → выходной слой. Различие задач сосредоточено в **выходном слое, функции потерь и формате y**.

**Регрессия:**

- Выход: `Dense(1)` без активации (линейная) — любое вещественное число.
- Loss: MSE или MAE; метрики: MAE, RMSE.

```python
model = keras.Sequential([
    layers.Dense(64, activation="relu", input_shape=(n,)),
    layers.Dense(64, activation="relu"),
    layers.Dense(1)])
model.compile("adam", loss="mse", metrics=["mae"])
```

**Классификация:**

- 2 класса: `Dense(1, activation="sigmoid")` + binary_crossentropy.
- N классов: `Dense(N, activation="softmax")` + (sparse_)categorical_crossentropy.

**Применение к табличным данным** — естественный вход: вектор масштабированных и закодированных признаков. Dense-сети — основной нейросетевой инструмент для таблиц.

**Применение к изображениям** — изображение нужно развернуть в вектор: `layers.Flatten(input_shape=(28,28))` превращает 28×28 в вектор из 784 чисел, дальше обычные Dense-слои. Работает на простых наборах (MNIST), но плохо масштабируется (см. вопрос 17).

## Вопрос 17. Ограничения полносвязных сетей на изображениях

**Проблема 1 — потеря пространственной структуры.** Flatten разрушает 2D-организацию: соседние пиксели, формировавшие границу или текстуру, оказываются в произвольных местах длинного вектора. Сеть больше «не знает», какие пиксели были рядом, и должна заново выучивать пространственные связи из чисел.

**Почему соседство важно.** Смысл изображения — в локальных структурах: **границы** (резкие перепады яркости между соседними пикселями), **текстуры** (повторяющиеся локальные узоры — трава, вода, асфальт), **формы** (комбинации границ). Объект определяется взаимным расположением частей, а не значениями отдельных пикселей. Для пространственных данных (снимки) это критично: дорога — это длинная узкая структура, а не набор серых пикселей.

**Проблема 2 — взрыв числа параметров.** Цветное изображение 200×200×3 = 120 000 входов; первый Dense-слой на 1000 нейронов = 120 млн весов. Это медленно, требует огромных данных и гарантированно переобучается.

**Проблема 3 — нет инвариантности к сдвигу.** Dense-сеть учит признак «кошка в левом верхнем углу» отдельно от «кошка в центре»: при сдвиге объекта на пиксель весь входной вектор меняется. CNN решает это разделяемыми весами фильтров.

**Вывод:** Dense по изображениям приемлем только для маленьких простых картинок; для реальных задач нужны свёрточные сети, которые сохраняют и используют пространственную структуру.

## Вопрос 18. Свёрточные нейронные сети (CNN)

**CNN** — сети для данных с пространственной структурой (изображения, снимки). Идея: признаки извлекаются **локально** скользящим окном, веса которого одинаковы для всех позиций.

**Операция свёртки.** **Фильтр (ядро, kernel)** — маленькая матрица обучаемых весов (3×3, 5×5). Он скользит по изображению; в каждой позиции вычисляется сумма поэлементных произведений ядра и накрытого участка (+bias, затем ReLU). Результат всех позиций — **карта признаков (feature map)**: 2D-карта «где на изображении встретился этот признак».

```python
layers.Conv2D(filters=32, kernel_size=(3,3), activation="relu", input_shape=(64,64,3))
# 32 фильтра → 32 карты признаков
```

**Локальные признаки.** Каждый фильтр учится реагировать на свой паттерн: вертикальная граница, угол, пятно цвета, текстура. Слой из 32 фильтров даёт 32 разных «детектора», работающих по всему изображению.

**Отличия от полносвязных сетей:**

- **Локальность:** нейрон видит только окно 3×3, а не всё изображение — структура соседства сохраняется (вход не разворачивается в вектор).
- **Разделяемые веса:** один и тот же фильтр применяется во всех позициях → признак узнаётся в любом месте (инвариантность к сдвигу) и параметров на порядки меньше (3×3×3×32 ≈ 900 весов против миллионов у Dense).
- Выход — не вектор, а набор карт признаков, сохраняющий геометрию.

Типичная архитектура классификатора: [Conv2D → ReLU → MaxPooling] × k → Flatten → Dense → softmax: свёрточная часть извлекает признаки, полносвязная — классифицирует.

---

## Вопрос 19. Pooling-слои

**Pooling (субдискретизация)** — слой без обучаемых параметров, уменьшающий пространственный размер карт признаков.

**MaxPooling2D(2×2)** — делит карту на блоки 2×2 и из каждого берёт максимум. Размер карты падает вдвое по каждой оси (28×28 → 14×14), число карт не меняется.

```python
layers.MaxPooling2D(pool_size=(2, 2))
```

**Зачем:**

1. **Снижение вычислительной сложности** — после пулинга карта в 4 раза меньше, следующие слои быстрее, меньше памяти и риска переобучения.
2. **Выделение устойчивых признаков** — максимум в окне отвечает на вопрос «есть ли признак в этой области», игнорируя точную позицию в пределах окна. Небольшой сдвиг или шум не меняет выход → устойчивость (локальная инвариантность) к малым смещениям.
3. **Рост рецептивного поля** — после уменьшения карты следующий фильтр 3×3 «видит» больший участок исходного изображения, что позволяет глубоким слоям собирать крупные структуры.

**AveragePooling** — среднее вместо максимума (сглаживает, используется реже; GlobalAveragePooling — усреднение всей карты в одно число, замена Flatten в современных сетях).

Чередование Conv → Pool по мере углубления: пространственный размер падает, число карт признаков растёт — сеть обменивает «где» на «что».

## Вопрос 20. Представление признаков в CNN

**Иерархия признаков.** CNN строит признаки послойно, от простого к сложному:

- **Первые слои** — элементарные признаки: границы разной ориентации, перепады яркости, цветовые пятна, простые текстуры. Эти фильтры похожи на универсальные детекторы и почти одинаковы для любых задач.
- **Средние слои** — комбинации простого: углы, дуги, повторяющиеся узоры, фрагменты объектов (глаз, колесо, участок крыши).
- **Глубокие слои** — высокоуровневые абстракции: целые объекты и их конфигурации («морда собаки», «здание», «перекрёсток»). Карты маленькие пространственно, но каналов много: информация «где» сжата, информация «что» обогащена.

Именно поэтому работает transfer learning: ранние слои предобученной сети переносимы на новые задачи, переучивать нужно в основном верхние.

**Карты активаций** — выходы промежуточных слоёв для конкретного входного изображения. Их визуализация показывает, какие участки изображения активировали каждый фильтр.

```python
activation_model = keras.Model(inputs=model.input,
                               outputs=[l.output for l in model.layers[:4]])
acts = activation_model.predict(img[None, ...])  # карты для одной картинки
```

**Использование:** понять, что сеть «смотрит» на нужные структуры (дорогу, а не тень от облака); диагностировать мёртвые фильтры (всегда нулевые карты); объяснить ошибки модели; убедиться, что признаки осмысленны. Это основной инструмент интерпретации свёрточных моделей.

## Вопрос 21. Переобучение и недообучение

**Недообучение (underfitting)** — модель не выучила закономерности даже на train: и обучающие, и валидационные метрики плохие. Причины: слишком простая модель (мало слоёв/нейронов), мало эпох, слишком маленький LR, плохие признаки.

**Переобучение (overfitting)** — модель запомнила обучающие примеры (включая шум) вместо общих закономерностей: на train отлично, на новых данных плохо. Запомнить ≠ обобщить.

**Связь сложности, данных и обобщения.** Ёмкость модели должна соответствовать объёму данных. Сложная модель на малом наборе имеет достаточно параметров, чтобы «выучить наизусть» каждый пример → переобучение. Простая модель на сложной задаче не способна выразить зависимость → недообучение. Чем больше обучающих данных, тем более сложную модель можно позволить без переобучения.

**Диагностика по метрикам (train vs validation):**

| Ситуация | Train | Validation |
|---|---|---|
| Норма | хорошо | близко к train |
| Переобучение | очень хорошо, loss ↓ | val_loss достиг минимума и **растёт**, зазор увеличивается |
| Недообучение | плохо | плохо (обе кривые на плато высоко) |

**Борьба с переобучением:** больше данных/аугментация, упростить модель, Dropout и регуляризация, EarlyStopping. **С недообучением:** усложнить модель, дольше учить, поднять LR, улучшить признаки.

## Вопрос 22. Регуляризация: Dropout и BatchNormalization

**Регуляризация** — приёмы, ограничивающие склонность модели к переобучению: мешают ей просто запоминать train и заставляют учить устойчивые закономерности, улучшая обобщение.

**Dropout.** На каждом шаге обучения случайная доля нейронов слоя (rate, например 0.5) временно «выключается» (выходы зануляются, оставшиеся масштабируются). Каждый батч обучает «случайную подсеть».

- Эффект: нейроны не могут полагаться на конкретных соседей → не возникает хрупких совместных адаптаций; сеть учит избыточные, устойчивые признаки. Работает как ансамбль множества подсетей.
- На инференсе dropout **отключён** — работают все нейроны.

```python
layers.Dense(128, activation="relu"),
layers.Dropout(0.5),
```

**BatchNormalization.** Нормализует выходы слоя по текущему батчу (среднее 0, дисперсия 1), затем масштабирует и сдвигает обучаемыми параметрами γ и β.

- Эффект: распределения входов слоёв перестают «плыть» в ходе обучения → обучение **стабильнее и быстрее**, можно больший LR, сглаживается ландшафт потерь; слабый дополнительный регуляризующий эффект (шум батчевой статистики).
- На инференсе использует накопленные скользящие среднее/дисперсию.
- Типичное место: Conv/Dense → BatchNorm → ReLU.

Итого: Dropout — главным образом против **переобучения**; BatchNorm — главным образом за **стабильность и скорость** обучения. Часто используются вместе.

## Вопрос 23. Колбэки: EarlyStopping и ModelCheckpoint

**Колбэк (callback)** — объект, который Keras автоматически вызывает в ходе `fit` (по окончании эпохи/батча), позволяя управлять обучением без вмешательства человека.

**EarlyStopping** — остановка при отсутствии улучшений:

```python
keras.callbacks.EarlyStopping(
    monitor="val_loss",          # что отслеживать
    patience=10,                 # сколько эпох ждать улучшения
    restore_best_weights=True)   # вернуть веса лучшей эпохи
```

Если `val_loss` не улучшается `patience` эпох подряд — обучение прекращается. Зачем: не пережигать время, и главное — не дать модели уйти в переобучение после прохождения минимума val_loss. `restore_best_weights=True` возвращает модель в лучшее состояние, а не оставляет последнее.

**ModelCheckpoint** — сохранение модели в процессе обучения:

```python
keras.callbacks.ModelCheckpoint(
    "best.keras",
    monitor="val_loss",
    save_best_only=True)   # перезаписывать только при улучшении
```

После каждой эпохи проверяет метрику и сохраняет файл, только если она улучшилась → на диске всегда лучшее состояние модели. Страхует от сбоев и от ухудшения на поздних эпохах.

**Совместно:** ставят запас эпох (например, 200) + оба колбэка: обучение само остановится в нужный момент, лучшая модель сохранена. Другие полезные колбэки: ReduceLROnPlateau (снижение LR при застое), TensorBoard (логирование).

```python
model.fit(X, y, epochs=200, validation_split=0.2, callbacks=[es, mc])
```

## Вопрос 24. Transfer Learning

**Идея.** Не учить CNN с нуля, а взять сеть, предобученную на огромном наборе (ImageNet, 1.4 млн картинок), и переиспользовать выученные ею признаки для своей задачи. Ранние слои CNN учат универсальные признаки (границы, текстуры — вопрос 20), которые полезны почти для любых изображений.

**Зачем:** своя задача обычно имеет мало данных; обучение с нуля → переобучение и долгие недели. Transfer learning даёт высокое качество на сотнях–тысячах примеров.

**Схема (feature extraction):**

1. Взять предобученную базу **без классификационной верхушки**: `base = keras.applications.VGG16(weights="imagenet", include_top=False)`.
2. **Заморозить** её слои: `base.trainable = False` — веса не обновляются, признаки сохраняются, обучается только новая часть.
3. **Заменить классификационную часть** — добавить свою «голову» под свои классы: GlobalAveragePooling → Dense → `Dense(n_классов, softmax)`.
4. Обучить голову на своих данных (база работает как фиксированный экстрактор признаков).

**Fine-tuning (дообучение):** после обучения головы можно разморозить верхние слои базы и дообучить их с **очень маленьким LR** (например, 1e-5), чтобы аккуратно адаптировать высокоуровневые признаки под специфику данных (например, спутниковые снимки вместо фотографий), не разрушив предобученные веса.

```python
base.trainable = False
model = keras.Sequential([base, layers.GlobalAveragePooling2D(),
                          layers.Dense(256, activation="relu"),
                          layers.Dense(5, activation="softmax")])
```

## Вопрос 25. Глубокие архитектуры и skip connections

**Почему архитектуры усложняются.** Глубина даёт более богатую иерархию признаков (вопрос 20), но простое наращивание слоёв упирается в проблемы: **затухающие градиенты** (при backprop через десятки слоёв градиент перемножается на множители <1 и стремится к нулю — ранние слои перестают учиться) и **деградацию** (очень глубокая «простая» сеть обучается хуже более мелкой). Поэтому современные CNN — это не просто стопки слоёв, а блоки с продуманными путями прохождения информации (ResNet, U-Net и др.).

**Skip connection (остаточная/обходная связь)** — соединение, передающее выход раннего слоя напрямую в более поздний, минуя промежуточные слои. Два вида:

- **Сложение (ResNet):** y = F(x) + x — блок учит «поправку» (остаток) к входу. Градиент течёт назад напрямую через тождественную связь → затухание устраняется, можно обучать сети в сотни слоёв.
- **Конкатенация (U-Net):** карты признаков раннего слоя присоединяются каналами к позднему — поздний слой видит и абстрактные, и детальные признаки.

**Значение для сохранения признаков и пространственных деталей.** При прохождении через свёртки и пулинги мелкие детали (точные границы, тонкие объекты) теряются. Skip connections «пробрасывают» детальные карты ранних слоёв вглубь сети, позволяя восстановить точную локализацию. Это критично в сегментации: в U-Net именно skip-связи дают точные границы объектов (вопрос 29).

## Вопрос 26. Автоэнкодеры

**Автоэнкодер** — сеть, обучаемая восстанавливать на выходе свой собственный вход. Обучение без разметки: X — и вход, и цель; loss — ошибка восстановления (MSE, binary crossentropy).

**Архитектура encoder–decoder:**

- **Encoder** сжимает вход до компактного скрытого представления: для изображений — Conv2D + MaxPooling (размер падает).
- **Бутылочное горлышко (latent / скрытое представление)** — узкий слой, код данных малой размерности. Из-за узости сеть не может скопировать вход и вынуждена выучить **самое существенное** в данных.
- **Decoder** разворачивает код обратно в полный размер: UpSampling2D / Conv2DTranspose (вопрос 27).

```python
# encoder: 28×28 → код;  decoder: код → 28×28
autoencoder.compile("adam", loss="mse")
autoencoder.fit(X_train, X_train, ...)   # вход = цель!
```

**Применения:**

- **Сжатие** — латентный код как компактное представление (нелинейный аналог PCA).
- **Удаление шума (denoising)** — на вход подают зашумлённые изображения, целью ставят чистые; сеть учится восстанавливать сигнал и убирать шум.
- **Восстановление/обработка изображений** — дорисовка повреждённых областей, повышение качества.
- **Поиск аномалий** — модель, обученная на «нормальных» данных, плохо восстанавливает аномальные → большая ошибка восстановления = сигнал аномалии.
- Encoder–decoder — концептуальная основа сегментационных сетей (U-Net) и генераторов pix2pix.

## Вопрос 27. Декодер: UpSampling2D и Conv2DTranspose

**Задача декодера** — восстановить пространственный размер: encoder сжал изображение до маленьких карт признаков, decoder должен вернуть полное разрешение (например, 7×7 → 28×28). Нужны операции, **увеличивающие** размер карт — «обратные пулингу».

**UpSampling2D** — простое масштабирование без обучаемых параметров: каждый пиксель повторяется в блок 2×2 (или билинейная интерполяция). Размер ×2, содержание не «придумывается». Поэтому обычно идёт в паре со свёрткой, которая сглаживает и дорабатывает результат:

```python
layers.UpSampling2D((2,2)),
layers.Conv2D(64, (3,3), activation="relu", padding="same")
```

**Conv2DTranspose (транспонированная свёртка)** — **обучаемая** операция увеличения: каждое входное значение умножается на ядро и «разбрасывается» в выходную область с перекрытием; со stride=2 размер удваивается. Сеть сама учится, как заполнять новые пиксели.

```python
layers.Conv2DTranspose(64, (3,3), strides=2, padding="same", activation="relu")
```

**Сравнение:** UpSampling — дешёвый, без параметров, без артефактов; Conv2DTranspose — гибче (учится), но больше параметров и возможны «шахматные» артефакты при неудачном сочетании размера ядра и шага.

Типичный decoder: несколько блоков [увеличение ×2 → Conv2D], зеркально повторяющих encoder, и финальный Conv2D с sigmoid (восстановление изображения в [0,1]) или softmax по классам (сегментация).

## Вопрос 28. Семантическая сегментация пространственных данных

**Семантическая сегментация** — присвоение класса **каждому пикселю** изображения. Результат — маска того же размера, что вход, где значение пикселя = номер класса.

**Отличие от классификации изображения:** классификация отвечает «что на снимке?» одним классом на всё изображение; сегментация отвечает «что находится в каждой точке?» — выход не вектор вероятностей, а попиксельная карта классов. Это переход от «что» к «что и где, с точностью до пикселя».

**Пиксельная классификация.** Каждый пиксель получает вектор вероятностей по классам (softmax по каналам), класс пикселя — argmax. Выход сети: тензор H×W×N_классов. Loss — попиксельная кросс-энтропия (или Dice/Focal, вопрос 31).

**Применение к пространственным данным (снимки ДЗЗ, аэрофото):**

- выделение **дорог** (связная сеть, оценка протяжённости),
- **зданий** (картографирование застройки, контроль самостроя),
- **воды** (мониторинг водоёмов, паводков),
- **растительности** (леса, сельхозкультуры, вырубки),
- классификация типов землепользования по пикселям.

Итог сегментации снимка — тематическая карта: каждому пикселю местности присвоен тип поверхности, по маскам считают площади и контуры объектов. Стандартная архитектура для таких задач — U-Net (вопрос 29).

## Вопрос 29. Архитектура U-Net

**U-Net** — encoder–decoder сеть для семантической сегментации (изначально — медицинские изображения; стандарт и для снимков ДЗЗ). Название — от U-образной схемы.

**Строение:**

- **Сжимающий путь (encoder, левая ветвь U):** повторяющиеся блоки [Conv2D ×2 → MaxPooling]. Пространственный размер падает (например, 256→128→64→32), число каналов растёт. Сеть накапливает **семантику** («что здесь?»), теряя точную локализацию.
- **Расширяющий путь (decoder, правая ветвь U):** блоки [увеличение разрешения (Conv2DTranspose/UpSampling) → Conv2D ×2]. Размер восстанавливается до исходного, каналы уменьшаются. Выход — Conv2D(N_классов, 1×1) + softmax: попиксельные вероятности.
- **Skip connections (перемычки U):** карты признаков каждого уровня encoder **конкатенируются** с картами соответствующего уровня decoder одинакового размера.

**Связь с encoder–decoder:** U-Net — это автоэнкодероподобная схема «сжатие → восстановление», но цель не воспроизвести вход, а выдать маску классов, и добавлены skip-связи.

**Роль skip connections.** В глубине сети маски были бы грубыми: точные позиции границ утрачены пулингом. Skip-связи передают в decoder **детальные карты ранних слоёв** (точные границы, мелкие объекты). Decoder совмещает семантику глубоких слоёв («это здание») с пространственной точностью ранних («граница проходит именно здесь») → точные контуры и сохранение мелких деталей. Без skip-связей границы объектов получаются размытыми, мелкие объекты исчезают.

## Вопрос 30. Подготовка данных для U-Net

**Данные:** пары «изображение — маска». **Маска** — изображение того же размера, где каждый пиксель помечен классом. Часто маски размечены цветами (RGB): дорога — синий, здание — красный и т.д.

**Этапы подготовки:**

1. **Разбиение на патчи.** Снимки ДЗЗ огромны (10 000×10 000) и не помещаются в память GPU. Изображение и маску режут на патчи фиксированного размера (256×256 или 512×512), возможно с перекрытием. Ключевое: изображение и маска режутся **одинаково** — i-й патч маски точно соответствует i-му патчу изображения.
2. **Преобразование RGB-масок в числовые метки.** Сети нужен номер класса, а не цвет. Каждому цвету сопоставляют индекс: (0,0,255)→0 (вода), (255,0,0)→1 (здание)… Получают маску H×W с целыми метками; далее либо sparse categorical crossentropy, либо one-hot (H×W×N) с categorical crossentropy.

```python
mask_labels = np.zeros(mask.shape[:2], dtype=np.uint8)
for idx, color in enumerate(palette):
    mask_labels[np.all(mask_rgb == color, axis=-1)] = idx
```

3. **Нормализация изображений** — пиксели /255 → [0,1] (маски НЕ нормализуются — это метки!).
4. **Согласованная предобработка.** Любая геометрическая операция (resize, повороты, отражения, кропы при аугментации) применяется **синхронно** к изображению и маске, иначе разметка «съедет». Resize маски — только методом ближайшего соседа (интерполяция создала бы несуществующие классы).
5. Разбиение пар на train/val/test (патчи одного исходного снимка лучше не разносить по разным выборкам во избежание утечки).

## Вопрос 31. Метрики и функции потерь в сегментации

**Pixel accuracy** — доля верно классифицированных пикселей. Проста, но **обманчива при дисбалансе**: если дороги занимают 2% снимка, модель «всё — фон» даёт accuracy 0.98, не найдя ни одной дороги.

**IoU (Intersection over Union, коэффициент Жаккара)** — для класса: IoU = |A∩B| / |A∪B| — площадь пересечения предсказанной и истинной масок к площади их объединения. 1 — идеальное совпадение; 0 — нет пересечения. Считается **по каждому классу**, усредняется в mean IoU — основная метрика сегментации, нечувствительная к доле фона.

**Dice-коэффициент** — Dice = 2|A∩B| / (|A|+|B|). Родственен IoU (монотонно связаны), чуть мягче штрафует частичные несовпадения. Широко используется в сегментации малых объектов.

**Функции потерь:**

- **Попиксельная кросс-энтропия** — базовый вариант; при дисбалансе редкие классы почти не влияют на loss.
- **Dice Loss = 1 − Dice** — оптимизирует непосредственно перекрытие масок; малые классы влияют на loss наравне с большими → хорошо при дисбалансе.
- **Focal Loss** — модифицированная кросс-энтропия: FL = −(1−p)^γ·log(p). Множитель (1−p)^γ занижает вклад уже легко классифицируемых пикселей (фона) и фокусирует обучение на трудных и редких.
- **Комбинированные** — например, CE + Dice Loss: кросс-энтропия даёт стабильные градиенты, Dice — внимание к перекрытию и редким классам. Часто лучший практический выбор.

## Вопрос 32. Дисбаланс классов в сегментации

**Суть проблемы.** На пространственных снимках классы крайне неравномерны: фон/растительность — 80–95% пикселей, дороги, здания, автомобили — единицы процентов. Loss и accuracy усредняются по пикселям, поэтому выгоднее всего «угождать» массовым классам, а редкие игнорировать.

**Малые и редкие объекты** страдают вдвойне: их мало в данных (мало сигналов в loss) и они малы по площади (несколько ошибочных пикселей на границе — уже большая относительная ошибка; после пулинга узкие объекты вообще могут исчезать из карт признаков).

**Почему «общая точность высокая, а важные классы выделяются плохо»:** общая accuracy — взвешенная по площади; доминирующий фон классифицируется легко и обеспечивает 0.9+ почти автоматически. Модель может полностью пропускать класс «дорога», теряя при этом <2% accuracy. Высокая общая метрика маскирует провал на содержательно важных классах.

**Что делать:**

- **Анализ по отдельным классам** — обязательный: per-class IoU/Dice, per-class precision/recall, матрица ошибок. Смотреть худшие классы, а не среднее.
- Loss с учётом дисбаланса: взвешенная кросс-энтропия (больший вес редким классам), Dice Loss, Focal Loss, комбинации (вопрос 31).
- Данные: сэмплирование патчей с присутствием редких классов, аугментация таких патчей.
- Метрику выбора модели брать сбалансированную (mean IoU, macro-F1), а не pixel accuracy.

## Вопрос 33. Генеративные модели

**Генеративная модель** учится распределению данных, чтобы **создавать новые** примеры, похожие на обучающие, — а не предсказывать метку.

**Отличие от классификации и регрессии.** Дискриминативные задачи: вход → компактный ответ (класс, число); есть единственный правильный ответ, ошибка измеряется напрямую (loss против ground truth). Генерация: вход (часто случайный шум или изображение-условие) → **новый объект** (изображение); правильных ответов бесконечно много — любой реалистичный результат хорош. Модель учит само распределение данных, а не границу между классами.

**Задачи:**

- создание новых данных (синтетические лица, текстуры, дополнение датасетов);
- восстановление изображений (дорисовка повреждённых областей, повышение разрешения, раскрашивание);
- преобразование изображений (стиль, схема → фотореалистичный снимок, снимок → карта — image-to-image, вопрос 35).

**Особенность оценки качества.** Привычные метрики не работают: нет эталона для сравнения «пиксель в пиксель» (низкий MSE даже вреден — усреднённые размытые картинки). Качество = реалистичность + разнообразие:

- **визуальный анализ человеком** — основной практический способ (регулярно смотреть сгенерированные примеры по ходу обучения);
- косвенные числовые метрики (FID/IS — сравнение распределений признаков реальных и сгенерированных изображений);
- для условной генерации с эталоном — попиксельные метрики (L1) как дополнение.

## Вопрос 34. GAN — генеративно-состязательные сети

**GAN** — пара сетей, обучаемых в противоборстве:

- **Генератор (G):** вход — **случайный вектор** z (шум из нормального распределения, например 100 чисел); выход — изображение. Случайность входа = источник разнообразия: каждый z даёт новую картинку; латентное пространство отображается в пространство изображений.
- **Дискриминатор (D):** бинарный классификатор «реальное изображение или сгенерированное»; вход — картинка, выход — вероятность «реальная».

**Состязательное обучение.** Аналогия: фальшивомонетчик (G) против эксперта (D). Шаг обучения:

1. Обучить D: реальные изображения → метка 1, сгенерированные → метка 0 (G заморожен).
2. Обучить G (через объединённую модель при замороженном D): G стремится, чтобы D назвал его картинки реальными (метка 1) — т.е. учится обманывать D.

Сети совершенствуются друг против друга: D всё лучше ловит подделки, G делает всё реалистичнее. Идеал — D не отличает (выдаёт ~0.5).

**Особенности обучения.** GAN капризны: нужен **баланс** сил G и D (если D слишком силён — G не получает полезного градиента; слишком слаб — G обманывает примитивно); типичные проблемы — mode collapse (G выдаёт однообразные картинки), нестабильность и осцилляции; кривые loss неинформативны о качестве (это игра, а не спуск к минимуму) → обязателен **визуальный анализ** генерируемых изображений по ходу обучения (сохранять сетку примеров каждые N эпох).

## Вопрос 35. Условные GAN и Pix2Pix

**Условный GAN (cGAN).** В обычном GAN управлять результатом нельзя — что выпадет из шума, то и получим. В cGAN генератору и дискриминатору дополнительно подаётся **условие** (метка класса, текст, изображение): G генерирует объект, соответствующий условию (например, заданную цифру), D проверяет и реалистичность, и **соответствие условию** (пара «условие + картинка»).

**Pix2Pix** — cGAN для **преобразования изображения в изображение** (image-to-image translation): условие — целое входное изображение. Примеры: схема → фотореалистичный фасад, контур → объект, ч/б → цвет, спутниковый снимок → карта (и наоборот), день → ночь. Обучение **парное**: каждому входу соответствует эталонный выход.

**Архитектура:**

- **Генератор — U-Net-подобный:** encoder–decoder со skip-связями. Вход и выход — изображения одной геометрии, и skip-связи передают точные пространственные детали (границы, контуры) с входа на выход — без них результат размыт.
- **Дискриминатор (PatchGAN):** получает **пару** (входное изображение, выходное) и оценивает реалистичность не всего изображения целиком, а локальных патчей (например, 70×70) — «каждый кусочек выглядит реальным?». Это улучшает текстуры и детали.
- **Loss генератора комбинированный:** adversarial loss (обмануть D) + **L1-loss** к эталону (близость к правильному ответу попиксельно). L1 отвечает за общую структуру, GAN-часть — за резкость и реалистичность деталей.

## Вопрос 36. Классификация vs детекция vs сегментация

Три задачи компьютерного зрения различаются **типом результата**:

| Задача | Вопрос | Результат | Пример выхода |
|---|---|---|---|
| **Классификация изображения** | Что на изображении? | один класс (вектор вероятностей) на всё изображение | «кошка», 0.93 |
| **Детекция объектов** | Какие объекты и где? | список объектов: класс + ограничивающая рамка (x, y, w, h) + уверенность | «машина (120,40,80,60) 0.91; машина (300,80,70,55) 0.87» |
| **Семантическая сегментация** | Что в каждом пикселе? | маска: класс **каждого пикселя**, размер = размеру изображения | карта H×W с метками классов |

**Градация детальности:** классификация — самый грубый ответ (изображение целиком, без локализации); детекция — локализация прямоугольником (где объекты и сколько их, но без точной формы); сегментация — максимальная детальность (точные контуры и площади, но без разделения на отдельные экземпляры: два слипшихся здания — одно «пятно» класса).

**Примеры на одном аэроснимке:** классификация — «застроенная территория»; детекция — рамки вокруг каждого автомобиля (подсчёт машин); сегментация — попиксельные маски дорог, зданий, воды, растительности (тематическая карта, вычисление площадей).

Выбор задачи определяется тем, какой ответ нужен приложению (вопрос 38).

## Вопрос 37. Детекция объектов и YOLO

**Детекция** — найти на изображении все объекты: для каждого предсказать класс, ограничивающую рамку и уверенность.

**Идея YOLO (You Only Look Once).** Одноэтапный детектор: изображение проходит через CNN **один раз**, и сеть **одновременно** предсказывает всё. Изображение делится сеткой (например, 13×13); каждая ячейка отвечает за объекты, чьи центры в неё попали, и предсказывает: координаты рамок (x, y, w, h), **confidence** и вероятности классов. Один проход → высокая скорость, работа в реальном времени (в отличие от двухэтапных детекторов типа Faster R-CNN: сначала кандидаты областей, потом их классификация — точнее, но медленнее). Постобработка — NMS (non-maximum suppression): удаление дублирующих рамок одного объекта, остаётся рамка с максимальной уверенностью.

**Метрики и понятия:**

- **Confidence score** — уверенность модели, что в рамке действительно есть объект и рамка точна; предсказания ниже порога отбрасываются.
- **IoU** — пересечение/объединение предсказанной и истинной рамок; детекция засчитывается как верная при IoU ≥ порога (обычно 0.5).
- **mAP (mean Average Precision)** — основная метрика детекции: для каждого класса строится кривая precision–recall (по убыванию confidence), считается площадь под ней (AP), затем усреднение по классам. Оценивает одновременно точность классификации, полноту находок и качество локализации.

## Вопрос 38. Выбор подхода для пространственного анализа

Метод выбирают от **требуемого результата**, типа данных и прикладной задачи:

**Классификация изображения** — когда нужен один ответ на снимок/патч целиком, локализация не нужна. Примеры: тип землепользования патча (лес/поле/застройка), есть ли на снимке вырубка, облачный/безоблачный кадр, сортировка снимков. Самый дешёвый по разметке (метка на изображение) и вычислениям.

**Детекция объектов** — когда нужно найти и **посчитать отдельные объекты**, а точная форма не важна. Примеры: подсчёт автомобилей на парковке, судов в порту, животных на аэрофото, отдельных деревьев. Результат — рамки: количество, позиции, размеры. Разметка — рамки (дороже меток, дешевле масок). Хороша для компактных объектов; неудобна для протяжённых структур (дорога в прямоугольник не вписывается).

**Семантическая сегментация** — когда нужны **точные границы и площади**, попиксельная карта. Примеры: картографирование дорог, контуры зданий, площади затопления/вырубок/полей, тематические карты покрытия. Самая дорогая разметка (попиксельные маски) и вычисления, но максимум пространственной детальности. Не различает экземпляры (для этого — instance segmentation).

**Логика выбора:** нужен ответ «что это?» → классификация; «сколько и где объектов?» → детекция; «где точно проходят границы, какие площади?» → сегментация. Учитывать: бюджет на разметку, размер объектов относительно пикселя, требования к скорости.

## Вопрос 39. Организация и сравнение экспериментов в MLflow

**Проблема.** Подбор модели — десятки запусков с разными гиперпараметрами. Без системы учёта результаты теряются: «какой LR был у той хорошей модели на прошлой неделе?». Ручные записи ненадёжны.

**MLflow** — инструмент трекинга ML-экспериментов. Структура: **эксперимент** (задача) → **запуски (runs)** — отдельные попытки обучения. Для каждого запуска фиксируются:

- **Параметры** (`log_param`) — гиперпараметры: LR, batch size, число эпох, архитектура, версия данных.
- **Метрики** (`log_metric`) — loss, accuracy, IoU…; можно по эпохам (динамика обучения).
- **Артефакты** (`log_artifact`) — файлы: сохранённая модель, графики обучения, конфиги, примеры предсказаний.
- Автоматически: время, длительность, код-версия (git commit).

```python
import mlflow
with mlflow.start_run():
    mlflow.log_param("lr", 0.001)
    mlflow.log_param("batch_size", 32)
    # ... обучение ...
    mlflow.log_metric("val_iou", 0.78)
    mlflow.log_artifact("best.keras")
```

**Таблица экспериментов.** Веб-интерфейс MLflow показывает все запуски таблицей: строки — запуски, столбцы — параметры и метрики. Можно сортировать по метрике, фильтровать, сравнивать запуски на одном графике. **Осмысленный выбор лучшей модели:** видно не «кажется, этот лучше», а точно — какая комбинация гиперпараметров дала лучший val IoU, воспроизводимо и с готовым артефактом модели. Это превращает подбор модели из хаоса в управляемый процесс.

## Вопрос 40. Воспроизводимость и переносимость ML-моделей

**Воспроизводимость** — возможность повторить результат: тот же код + те же данные + те же настройки → та же модель. **Переносимость** — модель работает не только в ноутбуке автора, но и в другой среде (сервер, другой компьютер, продакшен).

**Ключевой принцип: сохранять не только модель, но и правила предобработки.** Модель училась на преобразованных данных (масштабирование, кодирование, resize). На инференсе входы должны проходить **точно те же** преобразования с **теми же** параметрами:

- сохранять обученный scaler (`joblib.dump(scaler, "scaler.pkl")`) — те же mean/std или min/max, что на train;
- сохранять кодировщики (LabelEncoder, словари категорий, палитру классов масок);
- фиксировать размер входа, порядок каналов, нормализацию (/255 или нет).

Если на инференсе масштабировать иначе (например, fit scaler на новых данных) — модель получит данные «из другого мира» и будет тихо ошибаться, без сообщений об ошибке.

**Типичные проблемы переноса из учебного ноутбука:**

- предобработка размазана по ячейкам, выполнявшимся вразнобой — не повторить;
- «магические» переменные в памяти ноутбука, отсутствующие в коде;
- другие версии библиотек (TF/NumPy) в новой среде → другое поведение или несовместимость сохранённой модели;
- зашитые абсолютные пути, отсутствие фиксации random seed;
- данные изменились, а версия датасета не зафиксирована.

**Решения:** оформлять предобработку функциями/пайплайнами, сохранять артефакты предобработки рядом с моделью, фиксировать зависимости (requirements.txt), seed, версии данных; трекинг в MLflow (вопрос 39); контейнеризация (вопрос 41).

## Вопрос 41. Развёртывание моделей: контейнеры, ONNX, серверы инференса

**Развёртывание (deployment)** — перевод обученной модели из ноутбука в рабочую систему, где она обслуживает реальные запросы.

**Контейнеризация (Docker).** Контейнер упаковывает модель вместе со всем окружением: код, библиотеки нужных версий, зависимости. Запускается одинаково на любой машине — решает проблему «у меня работало»: среда инференса всегда идентична среде разработки. Контейнер с моделью можно тиражировать, обновлять и масштабировать независимо от остальной системы.

**ONNX (Open Neural Network Exchange)** — открытый **формат обмена** моделями между фреймворками. Модель, обученная в Keras/TF или PyTorch, экспортируется в единый формат .onnx и далее исполняется любой средой с поддержкой ONNX (ONNX Runtime) на разных платформах. Зачем: независимость продакшена от фреймворка обучения (обучили в PyTorch — запускаем в C++/Java-сервисе), оптимизации графа, единый формат для серверов инференса.

**Серверы инференса.** Специализированное ПО, которое загружает модели и отдаёт предсказания по сети (HTTP/gRPC API). **NVIDIA Triton Inference Server** — типичный пример: обслуживает модели разных форматов (ONNX, TensorFlow, PyTorch, TensorRT) одновременно; батчирует входящие запросы для эффективной загрузки GPU; ведёт версионирование моделей; масштабируется. Общая идея: приложение не импортирует TensorFlow — оно шлёт данные на сервер инференса и получает ответ; модель становится сетевым сервисом.

**Итоговая схема:** обучение → экспорт (ONNX) → упаковка (Docker) → сервер инференса (Triton) → API для приложений.

## Вопрос 42. Инференс обученной модели

**Инференс** — применение обученной модели к новым данным (только forward pass, без обучения и градиентов).

**Главное правило: повторить ключевые преобразования обучения.** Модель — функция, настроенная на данные конкретного вида. Любое расхождение предобработки между обучением и инференсом → неверные предсказания **без каких-либо ошибок выполнения** (самый коварный класс багов в ML).

**Что обязано совпадать:**

- **Масштабирование:** тот же scaler с параметрами, выученными на train (сохранённый mean/std), а не новый fit на входных данных; для изображений — та же нормализация (/255, или /127.5−1, или нормировка ImageNet — ровно как при обучении).
- **Размеры изображений:** тот же resize до входного размера сети (256×256 и тем же методом интерполяции).
- **Форматы входов:** порядок каналов (RGB vs BGR!), тип float32, форма тензора с батч-осью: (1, H, W, C) — `img[None, ...]`.
- **Кодирование признаков:** те же кодировщики категорий, тот же порядок столбцов таблицы.
- **Интерпретация выходов:** знать формат выхода — вероятности или логиты; argmax → индекс класса → имя класса через **тот же** LabelEncoder/словарь, что при обучении; для сегментации — argmax по каналам и обратная палитра цветов; денормализация выхода регрессии, если y масштабировался.

```python
img = cv2.resize(img, (256, 256))[..., ::-1]   # BGR→RGB как на обучении
x = (img / 255.0).astype("float32")[None, ...]
pred = model.predict(x)
cls = label_encoder.inverse_transform([pred.argmax()])
```

Практика: оформить предобработку одной функцией и использовать её и при обучении, и при инференсе.

## Вопрос 43. Языковые модели и ограниченность их знаний

**Языковая модель (LLM)** — нейросеть, обученная на огромных текстовых корпусах предсказывать следующий токен; за счёт этого генерирует связные ответы и «знает» факты из обучающих текстов.

**Ограниченность знаний без внешнего контекста:**

- **Знания заморожены** на момент обучения (knowledge cutoff) — о новых событиях и документах модель не знает.
- **Частных данных нет в обучении:** ваши учебные документы, внутренние регламенты, конспекты курса модель никогда не видела.
- **Память параметрическая и приблизительная:** знания «размазаны» по весам; модель воспроизводит типичное, а не точное.

**Причины ошибок при ответах по конкретным учебным документам.** Спросишь LLM «что сказано в методичке курса про функцию потерь в лабораторной №3» — модель не имеет доступа к методичке, но устроена так, что генерирует правдоподобный текст. Результат — **галлюцинации**: уверенный, гладкий, но выдуманный ответ (несуществующие разделы, перепутанные формулировки, «общие знания» вместо содержания документа). Модель не отличает «знаю из документа» от «звучит правдоподобно».

**Вывод — нужен поиск перед генерацией.** Чтобы отвечать по конкретным документам, модели нужно **подавать релевантные фрагменты этих документов прямо в контекст запроса**: сначала найти в документах места, относящиеся к вопросу, затем генерировать ответ, опираясь на них. Эта схема — Retrieval Augmented Generation (вопрос 44): ответ строится на извлечённых фактах, а не на «воспоминаниях» модели.

## Вопрос 44. Retrieval Augmented Generation (RAG)

**RAG** — схема «поиск + генерация»: перед ответом система находит в базе документов релевантные фрагменты и передаёт их LLM как контекст. Ответ опирается на реальные документы, а не только на память модели.

**Конвейер RAG:**

**Этап индексации (один раз, заранее):**

1. **Разбиение документов на фрагменты (чанки)** — длинные документы режутся на куски (сотни токенов), часто с перекрытием, чтобы не разрывать мысль.
2. **Построение embeddings** — каждый чанк прогоняется через embedding-модель → числовой вектор, кодирующий смысл текста.
3. **Сохранение в векторной базе** — векторы + исходные тексты чанков складываются в специализированное хранилище с быстрым поиском ближайших векторов.

**Этап ответа (на каждый вопрос):**

4. **Поиск релевантного контекста** — вопрос пользователя переводится в вектор той же embedding-моделью; векторная база находит top-k чанков с ближайшими векторами (семантически похожих на вопрос, даже без совпадения слов).
5. **Генерация ответа** — LLM получает промпт: «Используя следующие фрагменты документов: …, ответь на вопрос: …» и формулирует ответ **на основе найденного контекста**, с возможностью сослаться на источник.

**Что даёт:** ответы по частным/свежим документам без переобучения модели; меньше галлюцинаций (есть опора); проверяемость (видно, на каких фрагментах основан ответ); обновление знаний = переиндексация документов, а не обучение.

## Вопрос 45. Embeddings, чанки и векторная база данных

**Embedding** — представление текста числовым вектором фиксированной длины (например, 384 или 1536 чисел), полученным специальной нейросетью. Ключевое свойство: **близость по смыслу = близость векторов** (по косинусной мере). «Как уменьшить переобучение» и «способы борьбы с оверфиттингом» почти не пересекаются по словам, но их векторы близки — поэтому поиск семантический, а не по ключевым словам.

**Чанк** — фрагмент документа, единица индексации и поиска. Документ целиком кодировать нельзя: вектор «размоет» десятки тем, а LLM не нужен весь документ — нужны точные релевантные куски.

**Влияние размера чанков** (важный практический компромисс):

- **Слишком маленькие** (1–2 предложения): теряется контекст — фрагмент непонятен без окружения, ответ по обрывкам неполон.
- **Слишком большие** (страницы): в вектор попадает несколько тем → поиск менее точен; в контекст LLM попадает много нерелевантного «шума», ответы хуже и дороже.
- Практика: несколько сотен токенов (абзац–полстраницы) **с перекрытием** соседних чанков, чтобы мысль не разрезалась на границе; резать по смысловым границам (абзацы, разделы).

**Векторная база данных** — хранилище пар «вектор + текст чанка (+метаданные: документ, страница)», оптимизированное под быстрый поиск k ближайших векторов среди миллионов (FAISS, Chroma, Qdrant, pgvector).

**Качество контекста решает всё.** Ответ RAG не может быть лучше извлечённого контекста: если поиск принёс нерелевантные чанки (плохая нарезка, слабая embedding-модель, мало/много top-k), LLM либо ответит не по делу, либо начнёт галлюцинировать. Поэтому настройка нарезки и поиска — главный рычаг качества RAG-системы.
